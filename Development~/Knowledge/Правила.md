# Правила базы

Язык всего хранилища — русский. Давай заметкам, инструментам и командам редактора понятные русские названия. В инструкциях к сторонним программам рядом с переводом можно указать исходное имя команды для поиска в интерфейсе.

Одна мировая единица Unity равна 1 м. В интерфейсе, авторских данных, примерах, снимках и протоколах измеряй длину в м, площадь в м², объём в м³. Для углов используй градусы, для отношений — доли или проценты. При описании миграции указывай исходный коэффициент и физический размер. Исторические отчёты сохраняют измерения своей версии.

1. Начинай с [карты](Карта.md). Карточка описывает систему целиком: пользовательское действие, владельца данных, зависимости, сохранение, ограничения, проверку и открытые вопросы. Изменение одного поля оформляй в карточке системы.
2. У каждой записи есть type, status и updated. Для системы допустимы planned, in-progress, implemented и retired. Для решения — proposed, accepted и superseded. Для инструкций, карт и проверок — current. Обновляй дату, когда меняется содержание.
3. Существующие файлы проекта указывай в YAML sources как repo:путь/от/корня. Между заметками используй относительные Markdown-ссылки, пробелы кодируй как %20. Изображения храни во Вложения. Рабочие пути пользователя, ключи и кэши в базе не сохраняй.
4. План отделяет прямые требования от предложений. В решении указывай основание, дату и последствия. Для проверки записывай фактический сценарий и ограничения. Реализация, успешная компиляция, тесты и визуальная проверка имеют разные результаты.
5. При появлении новой системы добавь ссылку в карту. После исправления обнови затронутые карточки, сохрани прежний результат как датированную историю. Для одного утверждения установи один основной источник.
6. Из корня запускай `powershell -NoProfile -ExecutionPolicy Bypass -File Development~/Tools/Check-Knowledge.ps1`. Он проверяет метаданные, локальные ссылки, источники и конфигурацию Obsidian. Содержание и актуальность проверяй по фактическим файлам. При наличии Git дополнительно выполняй `git diff --check`.
7. Запускай только тесты, которые затрагивают изменённые или проверяемые системы. Полный применимый прогон выполняй, когда этого требует приёмка или изменение затрагивает общую интеграцию.
