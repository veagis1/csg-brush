# Работа над CSG Brush+

- Работай и общайся с владельцем по-русски. Всю базу знаний, отчёты и названия инструментов для пользователя веди на русском языке. Точные имена файлов, классов, команд сторонних программ и диагностик сохраняй там, где по ним нужно найти или воспроизвести результат.
- Отвечай кратко. При неоднозначном изменении требований уточни его у владельца.
- Веди разработку пакета здесь, в корне репозитория рядом с `package.json`. Используй отдельный Unity-стенд. Перенос проверенной версии в 8Circles выполняй по отдельному поручению владельца. Не подключай игру к рабочей копии через символьные ссылки или локальную зависимость.
- Начинай с [карты](Development~/Knowledge/Карта.md), [правил базы](Development~/Knowledge/Правила.md), [плана](Development~/Knowledge/План.md) и карточек затронутых систем. Сверяй текущее поведение по исходникам. Изменения согласованных требований вноси по указанию владельца. Предложения явно помечай.
- Сохраняй существующие GUID, .meta, сериализованные поля, лицензию и уведомления поставщиков. Новые инструменты Editor держи в Editor-сборках. При изменении формата проверяй загрузку старых данных и префабов. Авторские данные храни отдельно от сгенерированных мешей.
- Собственные поля, режимы, команды и сообщения Editor оформляй на русском. В подсказках объясняй действие, единицы, ноль, ограничения и зависимости. Для интерактивного редактирования предусматривай предпросмотр, отмену и Undo/Redo.
- Аксиома проекта — **одна мировая единица Unity равна 1 м**. В интерфейсе, авторских данных, новых примерах, снимках и протоколах указывай длину в м, площадь в м², объём в м³, углы в градусах. Доли и проценты сохраняют свой смысл.
- Перед запуском Editor сверяй версию и путь к отдельному проекту `Development~/Sandbox`. Для автоматизации используй актуальный официальный навык Unity CLI, статус ready и явный путь. На unity command передавай --caller plugin и --skill фактически применяемого навыка. Управление рабочим столом — только по отдельной просьбе владельца.
- Для тестов и сверок нескольких взаимосвязанных систем делегируй конкретную задачу агенту general на gpt-6.2-sol с усилием medium. Указывай проект, ограничения и ожидаемый результат. При недоступности делегирования тестов согласуй запуск с владельцем. Один поиск можно выполнить напрямую.
- После изменения кода прогоняй целевые проверки и полный применимый набор на итоговой версии. Сверяй имена и число тестов с каталогом. Сохраняй в базе среду, результат, точные падения, пропуски и ограничения. Для визуального инструмента проверяй также его взаимодействие в Inspector. При проверке Play Mode подтверждай продвижение кадров.
- Обновляй карточки затронутых систем и проверок вместе с кодом. Запускай локальный Development~/Tools/Check-Knowledge.ps1 после изменений базы. При наличии Git проверяй статус и git diff --check. Береги чужие незавершённые изменения.
- Перед завершением сохраняй результат, закрывай запущенные для задачи Editor, временные процессы и вкладки, восстанавливай настройки и проверяй освобождение блокировок. Исходные процессы пользователя сохраняй.

## Caveman и фоновая работа с Unity

- По просьбе владельца всегда работай в фоне, когда это технически возможно. Запускай свой стенд в `--batchmode` для компиляции, тестов и Play Mode. Видимый Editor открывай только на время проверки, для которой нужен графический интерфейс, и закрой сразу после неё. Остальные приложения также запускай без видимых окон, когда это возможно.

- По умолчанию применяй проектный навык `.agents/skills/caveman/SKILL.md`. Отвечай кратко по-русски. Переключай стиль или отключай его по просьбе владельца. В базе и коде сохраняй полные формулировки и точные результаты.
- Запускай Caveman, чтение журналов и проверенные блоки через обёртки из `Development~/Tools/Caveman`. Для первого просмотра журнала используй `read-log.cmd`; для исходников, различий и доказательств бери оригинал. Полные данные журнала доступны через `read-log.cmd --raw` или `caveman.cmd retrieve <handle>`. Перед написанием повторяемого скрипта проверь существующие блоки. Для браузерных задач применяй проектный Firefox MCP. [Настройки Caveman](Development~/Knowledge/Инструкции/Caveman.md).
- Используй [фоновый порядок работы со стендом](Development~/Knowledge/Системы/Автоматизация-Unity.md) при каждом задании Unity. Сцены, префабы, компиляцию и тесты веди через Unity CLI, Pipeline и API редактора. Указывай абсолютный путь отдельного Sandbox. Графический Editor для проверки инспектора также веди через программные команды. Дожидайся `ready` после запуска и перезагрузки домена. На `unity command` передавай `--caller plugin`, фактический `--skill` и для машинной проверки `--format json`.
- Сохраняй постоянные параметры фонового режима. В Play Mode проверь как минимум два значения номера кадра, после Stop сверь восстановление исходного режима Player. Заверши собственный Editor через CLI и проверь снятие блокировки Sandbox.
